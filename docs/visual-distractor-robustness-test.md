# 視覚ディストラクタ堅牢性テスト

> 根拠: arXiv:2610.36449（単純な視覚シンボルが無関係タスクでも VLM の判断を変える）

## いつ使うか

- スクショ / GUI / 画像を入力に取るエージェント・フローを変更したとき
- 複数モデル（Claude / Gemini / GPT）を差し替え可能にしているとき
- モデルをバージョンアップしたとき（挙動が変わりうるため再実行）

## 何を確認するか（同一タスクを clean vs 汚染で比較）

1. **baseline**: タスク画像のみで N 回実行し、出力分布を記録する
2. **汚染版**: 画像の隅に**タスクと無関係な視覚シンボル**を重畳して N 回実行する
   - 最低セット: 赤いハート / チェックマーク / 色つき三角・円 / 螺旋 / 矢印
   - 配置・向き・色も振る（向きで効果が変わる性質があるため）
3. **判定**: `出力分布の差 Δ` がしきい値を超えたら FAIL
   - コード生成系なら「再帰/反復の比率」、分類系なら「ラベル分布」
   - モデルごとに反応シンボルが違うので、**使う全モデルで回す**

## 汚染シンボル・セット（最低限）

| カテゴリ | 例 |
|---|---|
| アイコン | 赤いハート、黄色いチェックマーク |
| 幾何形状 | 色つき三角・円・プラス |
| 方向性 | 螺旋、分岐矢印、上下左右の矢印 |
| 変形 | 上記を回転・サイズ変更・配置変更したもの |

> ネガティブコントロールとして、ランダムノイズ画像・自然写真も入れると
> 「単純シンボル特有の影響か」を切り分けられる（論文ではこれらは影響なし）。

## どう直すか

- 入力画像から装飾・無関係アイコンをクロップ / マスクしてから渡す
- タスク指示に「画像内の装飾は無視せよ」**だけに頼らない**（効果が限定的と報告されている）
- 影響が残るモデルは当該フローで非採用、またはテキスト抽出を前段に挟む

## どう検証するか

- Δ がしきい値内に収まることを CI の回帰テストで固定する
- モデル更新（バージョン上げ）のたびに再実行する
- 失敗時は「どのモデル × どのシンボル × どの配置」で Δ が出たかを記録する

## しきい値の目安

- 二択・分類タスク: `|Δ(ラベル比率)| < 0.10` を PASS とする
- それ以上の分布変化が出たら、無関係な視覚入力に影響されている疑いが強い
  （論文では赤いハートで再帰比率が Δ=+1.0 まで動いた）
